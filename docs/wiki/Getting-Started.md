# Getting started

[← Wiki home](Home.md)

There are three ways to run War Room:

| | When | Sign-in |
|---|---|---|
| [Locally](#try-it-locally) | Trying it out, development | Developer sign-in (name and email, no password) |
| [Permanent install](#permanent-install) | Your standing incident-response capability | Okta and/or Microsoft Entra ID, optional SCIM |
| [War Room NOW](#war-room-now-temporary) | One incident, right now, on a throwaway server | Invite links plus 6-digit codes |

## Try it locally

Needs Node 24+ and Docker (for the LiveKit voice server).

```powershell
npm install
```

```powershell
npm run livekit:dev
```

```powershell
npm run dev
```

Open http://localhost:5173 and use **developer sign-in**. The first person to sign in becomes an admin. To try several people at once, use a second browser profile or a private window.

Development data is in `server/data/` (SQLite database plus generated keys). Delete that folder for a clean start.

## Permanent install

You need a Linux server with Docker and the Compose plugin, and a DNS name for it. HTTPS is not optional: browsers only allow microphones and screen sharing on secure pages.

1. **DNS:** add an A record, for example `warroom.example.com` → the server's public IP. Caddy (included) gets a Let's Encrypt certificate for it automatically.
2. **Firewall:** open TCP 80 and 443 (web and certificates), TCP 7881 and UDP 50000–50100 (voice and screen-share media).
3. **Start it:** get `docker-compose.yml`, `Caddyfile` and `livekit.yaml` from the repository (or clone it), then:

   ```
   APP_DOMAIN=warroom.example.com docker compose up -d
   ```

   This pulls `ghcr.io/tf-anguskong/warroom`. Pin a version with `WARROOM_VERSION=1.0.0`, or add `--build` to build from your clone.
4. **First admin:** `docker compose logs app` prints a **one-time setup link** (valid 24 hours). Open it, create the first admin, and you land in **Admin → Settings**.
5. **Connect sign-in:** set up Okta or Entra ID ([Sign-in and provisioning](Sign-in-and-Provisioning.md)), click **Test**, then **Save**. Changes take effect immediately.
6. **Optional:** email (for guest codes and sign-in codes), SCIM provisioning, and integrations.

There is no `.env` file to edit: everything is configured in **Admin → Settings** ([Settings reference](Settings-Reference.md)). The LiveKit key pair is generated by War Room and shared with the LiveKit container automatically.

## War Room NOW (temporary)

For a single incident, on any Linux server with Docker:

```
curl -fsSLO https://raw.githubusercontent.com/tf-anguskong/warroom/main/warroom-now.sh
bash warroom-now.sh up
```

The script asks for a DNS name (or offers a free `sslip.io` name), sets up the firewall, starts everything and prints your admin link. There is no identity provider: people join with single-use invite links plus 6-digit codes. When the incident is over, export the rooms to an encrypted `.warroom` file and destroy the server.

The full guide, including DNS, the IP allowlist, inviting people, exporting and teardown, is **[War Room NOW](../WARROOM_NOW.md)**.

## Your first incident

1. On the dashboard, click **Declare incident**. Give it a title, a severity (SEV1–SEV4), a summary, and choose sheet templates (IOC Tracker, Affected Assets, Action Items, Comms Log).
2. You start as **Incident Commander**. Assign the other roles from the right pane.
3. Click **Invite** (top bar) to bring in responders or guests, or **copy the war room link** and share it: people with an account join directly, everyone else can ask to join.
4. Click **Join Main Bridge** to start talking.
